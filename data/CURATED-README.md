# Manually checked event sample

`curated-events.json` contains 21 upcoming event listings checked against the linked venue, organizer, or ticket pages on November 5, 2026. It is a small hand-curated sample, not a complete or automatically updated calendar. Listings can change or sell out; check the linked sources before displaying them as current. Verify again and remove expired, canceled, or private events when refreshing the file.

Each record has a stable text `id`, `title`, broad `category`, `start_local` and optional `end_local` as ISO 8601 timestamps with UTC offset, and the IANA `timezone`. `time_type` states whether the first time is an event start, performance start, doors time, or an unspecified `listed_time` from the venue calendar. A listed or doors time should not be presented as the show start. Bingo Loco's two published performances have separate records; Latin Nights begins with the listed doors time and has a later salsa lesson. `venue` and `address` represent only published information; White Light Night spans Mid City and has no single street address. The organizer provides its event map.

`price_min_usd` is the lowest explicitly published admission price, including a child or advance price where stated in `description`. A null price means unknown, not free. `ticket_url` is null when a direct ticket destination was not checked. `age_restriction` contains the venue's published policy when known. `latitude` and `longitude` are null until verified, not zero. `source_urls` provide the evidence used for the record, and `checked_date` records when the listing was reviewed. Categories are descriptive labels assigned for this dataset, not official organizer classifications. Chelsea's calendar gives some times without saying whether they are doors or performance times. For Futurebirds the ticket page explicitly identifies the calendar time as doors, and gives an 8 p.m. performance.

## Mapping to the prototype

The app's existing `Event` model has `title`, `category`, `venue`, `time`, `price`, `activities`, `description`, `latitude` and `longitude` fields. Map shared text fields directly and format timestamps in the event's time zone, respecting `time_type`. The app currently uses integer IDs, relative `daysAway`, mandatory numeric prices and coordinates, and demo popularity, signups, and distance values; this file intentionally does not invent any of those. A proper integration needs model changes to preserve nullable values, use fixed dates, calculate distance only with verified coordinates and a user's location, and represent unknown popularity. `price_min_usd` can be a child or advance ticket price, so show the qualifying text rather than labeling every ticket with that number. This sample is a handoff and is not wired into either client.
